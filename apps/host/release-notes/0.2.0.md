Althar 0.2.0 for Linux adds workers and lets a window make projects on its home.

- Add a worker from **Settings › Computers** over SSH: it installs from this same signed release, which now carries the native worker, signs its agents in from the window and updates itself while it runs no task. Task leads, project setup, commands and private previews run on the workers a project is given.
- A home with no projects opens on its welcome. Make projects from the window, from a repository cloned on the home or a new one.
- Confirm permission answers from a paired desktop with a FIDO2 security key.
- `pair` also prints a link a phone can open, to show as a QR.
- Agents that fail to start say why, and a failure that may pass is tried again by itself. Claude Code adapter 0.112.0 and Codex adapter 2.12.0.
- Codex offers GPT-6.2 Sol, each account shows and runs its own models, and a plan that runs out moves to the same model elsewhere first.
- `/goal`, `/compact` and other slash commands in composers, and full sessions compact while idle.
- Update downloads are tried again after a lookup, connection or server error, and a failure says what went wrong.

**Updating from 0.1.0.** This release changes the stored-data format, so the window's **Update** stops without applying it. First check that your clients are ready for the new release and [make a separate export](https://github.com/AltharIDE/althar/blob/main/apps/host/README.md#os-sealed-keys-and-recovery) of the home: if the new release fails after starting, the home stays stopped with its data preserved. Then run this on the home, once:

```sh
sh "${XDG_DATA_HOME:-$HOME/.local/share}/althar-host-program/launcher" update --apply --allow-incompatible --wait
```

That's the launcher of a default install. If you installed with `--installation`, run the `launcher` in that directory and pass the same `--installation`. Add the `--profile` your home uses if it isn't the default. Adding a worker and the rest also need a desktop app new enough to have them.

**Known issue.** Adding a worker **With a code** doesn't work yet: the script and the release it downloads are looked for at an address that has neither. A machine you can reach over SSH can be added that way. One you can't has no working route in this release.

A home and its agents run as one OS user and share that user's file access. Use a dedicated account and code you trust.
