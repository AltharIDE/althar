What changed since 0.6.0.

Fewer things wait on you. A lead's commits now go up to its pull request by themselves, Claude Code runs what stays inside its sandbox without stopping to ask, and a pull request you queue from GitHub is followed like one Althar queued. Plan usage for Claude Code is fresh again, and a push that fails says why.

## New

- **A lead's commits push on their own.** On a task with an open pull request, what its lead commits goes up when its turn ends, even after you've looked, instead of waiting on Needs you for you to press Push. It only ever goes to the pull request's own branch, never to the default branch and never forced. While it's on its way the card says "1 commit going up to the PR" and offers neither Push nor Accept. Althar holds the push for you, and the card says why, if someone else pushed there ("Someone else pushed to PR #402"), if you stopped or interrupted the agent since, or if the push would need forcing or doesn't go through. It starts on in every project. To turn it off: Project settings › General › Push the lead's commits automatically. When you first open 0.6.1, commits already waiting on tasks with an open pull request go up, and with them any you made yourself in a task's folder and hadn't pushed.

## Improved

- **The sandbox is the line.** For Claude Code's leads and the coordinator, a command that stays inside their sandbox runs without Althar reading it first: loops, `$(…)`, heredocs and Python scripts no longer stop for a card. Your project's own Never and Ask me rules still hold there. On one Mac, people allowed 77 of the 78 cards such commands raised in two weeks. Agents without a sandbox (Codex, OpenCode, a review's lead, and everything on Windows and in the Linux Flatpak) keep the rules they had.
- **Git itself stops what can't be undone.** A push to the default branch, a force push, or deleting or rewinding a branch that isn't the task's is stopped wherever a lead's git runs from, a script included. When you allow one, that one command goes through, once, in that repository.
- **See how the asking went.** Project settings › Rules shows how each kind of ask and refusal went over the last 14 days, the sandbox's own refusals included.
- **A failed push says why,** in a sentence naming the host: the sign-in was refused, you don't have permission, the branch is protected, the host couldn't be reached or didn't answer, the remote has newer commits, or a hook said no, in its own words. Each comes with its way out: Try again, Connect, or what to do in a line. Git's own output sits behind Details, where it used to be a red command line running off the card.
- **Merging into main on this computer is as strict as git, and no stricter.** A task without a pull request now merges past uncommitted changes in your checkout, as long as they're in files the merge doesn't touch, and leaves them as they were. When it can't, it says so in a short line naming the files. The button reads "Merge into main on this Mac" ("this PC" or "this computer" elsewhere), and the card's file list keeps every file's name whole, shortening only its folder.
- **Several workspaces read clearly.** In Settings › Code hosts and trackers, a tracker signed in to more than one workspace lists each on its own row: the workspace first, who you're signed in as under it, and its own Disconnect beside it. One whose sign-in stopped working shows Sign in again on its row.
- Claude Code's adapter is 0.99.1 and Codex's is 2.5.0.

## Fixed

- **Claude Code's plan usage is fresh again.** Althar now reads it from Claude Code's own sessions as they run, where it used to drop those readings and fall back on asking Anthropic, which could leave the peek showing a whole 5-hour window left after a day of work. The coordinator steers new work by the same numbers. A window whose reset has passed drops out instead of showing all of its plan left, and an agent with none left to show says "Not read since reset".
- **A pull request queued from GitHub is followed.** Put one in the merge queue from GitHub's site or `gh`, and its task says "In the merge queue" instead of offering Accept and merge. It lands in Done when the queue merges it, and comes back to Needs you, with the reason, if the queue sends it back.
- A task that has just started from its plan no longer shows as Stopped, with "Invalid Date" and Carry on, while its folder is set up. Its card says "Installing dependencies" or "Setting up", and no time anywhere reads "Invalid Date" again.
- On Windows, a permission the coordinator would have allowed no longer comes to you because Windows still held the folder it decided in.
- Installing or upgrading with Homebrew no longer prints a warning about Althar's cask.

Tell us what breaks: Report a problem in the app, or https://github.com/AltharIDE/althar/issues
