# Allow everything: four paths

How should someone tell Althar to stop asking, for a whole project and for a single task? These are four ways to do it, A to D, plus B and C together. They are drawn with the kit’s own parts and fixtures only. Nothing is wired to the app.

One thing is the same in every path: **Never still holds, and no agent reads your credentials or reaches the code host except through Althar.** Each path says so where you turn allowing everything on.

Every group has its states as stories, each with a `scheme` control (light, or a dark stand-in), and a **Light and dark** story that lays the states side by side. The kit has no dark theme yet, so the dark one is a palette kept inside this exploration (`Scheme.module.css`). It shows how each mark holds up on dark. It isn’t a proposal for the kit’s dark theme.

## The card that has no “always allow”

A request on the project’s “Always ask me” list arrives with Never offered but not “Always allow”. Today the card doesn’t say why. Every path adds a line under the command: _Always allow isn’t offered: deploying or publishing is on Meridian’s “Always ask me” list, which comes before anything allowed._ The way out depends on the path:

- **A**: a link that opens the task’s menu at the switch.
- **B**: a link that opens the task’s words in the bar, at the dial.
- **C**: the card’s own last answer, “Yes, and stop asking on this task”, which gets past the list for this task only.
- **D**: a small menu in the card’s foot, “Allow everything for…”, with the three lengths.

In every path, once the task allows everything, whatever was waiting goes in one quiet line that opens to each command. It doesn’t come back if the task asks again, since it has already run.

## Recommendation

**B and C together**, as you leaned, with these choices:

1. **B is the model.** One dial, the same four words for the project and for a task, and the task’s bar as the one place that says where it stands and changes it, in both directions. The rules page lists the tasks that differ.
2. **C is a way into B, not a mode of its own.** The card’s last answer sets _this task_ to Allow everything and says so before you press. It never touches the project. Undo is B’s “Back to project default”, from the bar or from the line in the thread.
3. **From A, keep the quiet sentences.** On the rules page, what allowing everything sets aside dims and says why, as the kit already does. Leave out “Ignore Never too”: emptying the Never list is that switch, and it’s one you choose sentence by sentence.
4. **From D, keep “until this task finishes”** as what a task’s setting means: it ends with the task, and a reopened task asks again. Leave the timers out for now. If a timed one is wanted later, it belongs in the bar’s popover, not in a new pill.
5. **On the board and the home, say it only when a task allows everything.** The other modes aren’t worth a word on a card.

## Open questions

- Should a task set to Allow everything also set aside “Always ask me”? The project’s mode does today, and C depends on it for held cards. The other option is that held requests still ask, and the card says so.
- Is the word “Allows everything” right, or “Unrestricted”? The paths use both so you can compare them.
- When the project itself allows everything, every task’s bar says so in ink. Should the project’s own head say it once instead?

## Not in this exploration

- Nothing is wired to the runtime. The stories use fixtures only, under `src/explorations/AllowEverything`, which nothing imports and which is left out of the coverage gate.
- Two glyphs, a struck lock and an hourglass, aren’t in the kit’s icon table yet. They’re drawn locally (`ExploreIcon.tsx`).
- The permission card, the board card, and A’s and D’s task menus are drawn from the real components' markup, styles and words, with each path’s additions. The real components are unchanged.
